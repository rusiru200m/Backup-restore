    The app generates and encrypts a private key on the controller. No key path, key passphrase, or environment variable is needed for generated keys. Keys are named using the profile name above.

    Public key for VPS console setup 
    
          
    If SSH password login is disabled, add this public key as a new line in the selected account's ~/.ssh/authorized_keys through your VPS console or existing SSH client. Keep existing keys. The app's private key is never displayed.
    
        
    
        
    1. Trust the server once
    
        
        
    Trust on first connection: saves the first identity received; it is not independently verified. Later identity changes are blocked.
    
        
    Enter the VPS host and port above, then choose Trust this server. Saved server identities are checked automatically on every connection.
    
        
    
          Server fingerprint (optional verification)
          
          
          
    For extra assurance before choosing Trust this server, compare this fingerprint with your VPS console or an existing trusted SSH session. It identifies the server and is different from the generated SSH key fingerprint shown in the key selector.
    
          
    In your VPS provider console or an existing trusted SSH session, run this read-only command to display the server's public host key fingerprints. Compare the complete SHA256 value for the key type shown after reading.
    
          
    for key in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$key" -E sha256; done
    
          
    Reading the fingerprint in this app does not verify it by itself. If the values differ, stop and check the host, port, and server identity.
    
        
    
        
    2. Authorize the generated key
    
        
        
    The password is used only to add the public key to this VPS account. It is not saved. This requires SSH password login; otherwise use the public-key console setup above.
